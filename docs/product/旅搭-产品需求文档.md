# 旅搭 (BlockTrip) — 产品需求文档（PRD）

> 版本：v1.0 | 作者：产品团队 | 日期：2026-06-06
> 状态：草稿

## 1. 概述

### 1.1 背景与动机

旅游攻略短视频（抖音、小红书等）已成为用户出行前获取灵感的主要渠道，但**「收藏从未停止，行动从未开始」**。核心痛点在于：视频内容好看但信息高度分散，主观推荐真假难辨，用户仍需手动从视频中提取景点、餐厅、交通、预算等信息，再反复筛选、组合、调整才能形成可执行的旅行计划。整个过程耗时且体验割裂。

**旅搭** 是一款将旅游攻略视频 AI 拆解为标准化旅行模块（景点、饭店、交通、预算、避坑等卡片），并以「少儿编程」式拖拽拼装的方式，让用户像搭积木一样快速构建个性化旅行路线的工具型产品。

### 1.2 目标

| 类型 | 目标 | 衡量指标 |
|------|------|----------|
| 业务目标 | 成为旅游规划前序环节的入口级工具 | 月活用户 50 万（首年） |
| 用户目标 | 将「视频种草→行程落地」的时间从数小时缩短至 10 分钟以内 | 单用户平均规划时长 ≤10min |
| 体验目标 | 让旅行规划从繁琐的笔记整理变成直观的拼搭游戏 | NPS ≥ 40 |

### 1.3 范围

- **本期包含（MVP）**：抖音视频解析与 AI 模块化拆解、可视化拖拽拼装画布、基础分享与导出
- **本期不包含**：多语言攻略、实时预订闭环、社区 UGC 互动、离线模式

## 2. 竞品分析

| 竞品 | 定位 | 优势 | 劣势 | 我们的差异化 |
|------|------|------|------|-------------|
| **携程攻略/马蜂窝** | OTA 附属攻略社区 | 内容量大、权威性高 | 内容陈旧、UGC 质量参差、无视频解析 | 视频→结构化数据，实时性强 |
| **穷游行程助手** | 行程规划工具 | 行程模板丰富 | 依赖手动输入、内容获取成本高 | AI 自动提取，零手动录入 |
| **Notion/飞书文档** | 通用笔记工具 | 灵活自由 | 无旅游场景优化、无 AI 辅助 | 旅游垂直场景 + AI 智能拆解 |
| **抖音收藏夹** | 内容收藏 | 原生体验、内容丰富 | 纯收藏无法执行、信息未结构化 | 从收藏到行动闭环 |

## 3. 用户画像

**小夏**：22 岁大学生，热爱穷游，抖音重度用户
- 身份：大学生
- 核心目标：低成本玩透目的地，不想做繁琐攻略
- 主要痛点：收藏了很多抖音攻略视频，出发前还是一团乱，不知道从哪开始
- 技术熟练度：高

**阿杰**：30 岁互联网从业者，周末短途游爱好者
- 身份：上班族
- 核心目标：快速规划 2-3 天短途行程，追求效率
- 主要痛点：没时间整理攻略，希望一键生成可执行方案
- 技术熟练度：中

**林姐**：45 岁家庭游组织者
- 身份：妈妈
- 核心目标：为全家安排舒适安全的旅行
- 主要痛点：网上攻略太杂太主观，担心踩坑，需要直观的行程安排
- 技术熟练度：低

## 4. 用户旅程地图

| 阶段 | 用户行为 | 痛点 | 机会点 |
|------|----------|------|--------|
| **种草** | 在抖音刷到攻略视频，点赞收藏 | 收藏后不会回看，信息遗忘 | 打通抖音收藏，提醒整理 |
| **决策** | 确定目的地，开始规划 | 信息分散在多平台，整理耗时 | AI 一键提取视频核心信息 |
| **规划** | 打开多个攻略，手写/复制到笔记 | 手动录入繁琐，格式混乱 | 模块化拖拽拼装，像玩游戏 |
| **确认** | 反复调整顺序、查地图、算预算 | 需要多个 App 来回切换 | 内置地图预览 + 自动预算 |
| **分享** | 把行程发给同行伙伴 | 图片/文档格式不直观 | 一键生成精美行程海报 |
| **出行** | 现场对照行程游玩 | 纸质/截图不便查看 | 行程导出日历/地图导航 |

## 5. 用户故事

### 小夏（大学生穷游者）

- **US-001**：作为抖音重度用户，我想要粘贴抖音视频链接让 AI 自动拆解攻略信息，以便不用手动整理笔记
- **US-002**：作为预算敏感型旅行者，我想要看到每个模块的预估花费，以便控制整体旅行预算
- **US-003**：作为喜欢自由行的用户，我想要拖拽调整景点顺序并实时看到路线变化，以便规划最优游玩路径
- **US-004**：作为社交爱好者，我想要把拼好的行程生成精美海报分享到小红书，以便炫耀我的旅行规划

### 阿杰（上班族短途游）

- **US-005**：作为时间有限的用户，我想要上传录屏或直接粘贴链接就能自动提取信息，以便最快 5 分钟搞定行程
- **US-006**：作为追求效率的用户，我想要 AI 根据提取的模块智能推荐最优路线顺序，以便减少在地图上来回绕路
- **US-007**：作为实用主义者，我想要一键将行程导出到手机日历，以便出行当天按计划执行

### 林姐（家庭游组织者）

- **US-008**：作为非技术用户，我想要拖拽模块就能拼装行程，像搭积木一样简单，以便不用学习复杂操作
- **US-009**：作为家长，我想要看到每个地点的避坑提醒和安全提示，以便保护家人出行安全
- **US-010**：作为行程组织者，我想要把拼好的行程分享给家人并让他们能看懂，以便全家达成共识

## 6. 功能需求

### 6.1 功能清单

| ID | 功能 | 关联故事 | 描述 | 优先级 |
|----|------|----------|------|--------|

| F-003 | 模块卡片生成 | US-001, US-002 | 将解析结果生成为标准化模块卡片（景点卡/餐厅卡/交通卡/住宿卡/避坑卡/预算卡） | Must |
| F-004 | 可视化拼装画布 | US-003, US-008 | 提供无限画布，支持模块卡片的拖拽、添加、删除、排序操作 | Must |
| F-005 | 智能路线推荐 | US-006 | 基于地理位置和开放时间，AI 自动推荐最优游览顺序 | Should |

| F-007 | 预算自动计算 | US-002 | 根据卡片中的费用信息自动汇总总预算，按类别（门票/餐饮/交通/住宿）拆分 | Should |
| F-008 | 避坑提醒标注 | US-009 | 在对应模块上醒目标注避坑提示，支持点击查看详情 | Must |
| F-009 | 行程导出 | US-007 | 支持导出为日历文件（.ics）、PDF 行程单、图片海报 | Should |
| F-010 | 行程分享 | US-004, US-010 | 生成可分享的链接/海报，支持微信、小红书分享 | Should |
| F-011 | 用户账户 | US-010 | 支持手机号/微信登录，保存历史行程 | Could |
| F-012 | 多人协作 | US-010 | 支持邀请同行人共同编辑同一份行程 | Won't |

### 6.2 非功能需求

| 维度 | 需求 | 目标值 |
|------|------|--------|
| 性能 | 视频解析响应时间 | ≤15 秒（3 分钟内视频） |
| 性能 | 画布拖拽操作延迟 | ≤50ms |
| 性能 | 页面首次加载时间 | ≤2 秒 |
| 安全 | 用户数据存储 | 加密存储，不泄露视频解析内容 |
| 安全 | 第三方链接安全 | 仅支持白名单平台链接（抖音、B 站、小红书） |
| 可用性 | 系统可用性 | 99.5% |
| 可扩展性 | 视频解析并发 | 支持 100 QPS |
| 易用性 | 首次使用完成率 | ≥80% 用户无需教程完成首次拼装 |
| 兼容性 | 客户端 | iOS 14+ / Android 10+ / 微信小程序 |

### 6.3 功能依赖关系

```
F-001 (视频输入) → F-002 (AI 解析) → F-003 (模块生成) → F-004 (拼装画布)
```

## 8. 优先级

### 8.1 MoSCoW 矩阵

| ID | 功能 | 优先级 | 理由 |
|----|------|--------|------|
| F-001 | 视频输入 | **Must** | 核心入口，无输入则无后续流程 |
| F-002 | AI 视频解析 | **Must** | 产品核心差异化能力，无解析则无模块化数据 |
| F-003 | 模块卡片生成 | **Must** | 解析结果的载体，拼装的基础素材 |
| F-004 | 可视化拼装画布 | **Must** | 核心交互形式，产品灵魂功能 |
| F-008 | 避坑提醒标注 | **Must** | 核心价值主张之一（避坑），用户安全感来源 |
| F-005 | 智能路线推荐 | **Should** | 大幅提升规划效率，但用户可手动调整替代 |
| F-006 | 地图路线预览 | **Should** | 增强空间感知，辅助决策 |
| F-007 | 预算自动计算 | **Should** | 用户价值高，但 MVP 可用手动标注替代 |
| F-009 | 行程导出 | **Should** | 出行前必备环节，但 MVP 可用截图替代 |

## 9. 验收标准

### F-001 视频输入

**AC-F001-01：抖音链接输入（正常路径）**
Given 用户已打开 App 首页
When 用户在输入框粘贴一个有效的抖音视频链接并点击「开始解析」
Then 系统进入解析 Loading 状态，15 秒内返回解析结果

**AC-F001-02：录屏文件上传（正常路径）**
Given 用户已打开 App 首页
When 用户点击「上传录屏」选择一段 ≤5 分钟的本地视频并确认
Then 系统成功接收文件，进入解析流程

**AC-F001-03：无效链接（异常路径）**
Given 用户已打开 App 首页
When 用户粘贴一个非抖音/非白名单平台的链接
Then 系统提示「暂不支持该平台链接，目前支持：抖音、B 站、小红书」，不发起解析请求

**AC-F001-04：空输入（边界条件）**
Given 用户已打开 App 首页
When 用户未输入任何内容直接点击「开始解析」
Then 解析按钮置灰不可点击，或点击后提示「请输入视频链接或上传录屏」

### F-002 AI 视频解析

**AC-F002-01：解析成功（正常路径）**
Given 用户提交了有效的攻略视频
When AI 解析完成后
Then 系统提取出至少一种类型的模块卡片（景点/餐厅/交通/住宿/避坑/预算），并展示解析结果预览

**AC-F002-02：解析超时（异常路径）**
Given 用户提交了视频
When 解析时间超过 30 秒仍未完成
Then 系统提示「解析时间较长，请稍后查看结果」，并在后台继续处理，完成后推送通知

**AC-F002-03：非攻略视频（边界条件）**
Given 用户提交的视频内容不包含旅游攻略信息
When AI 解析完成
Then 系统提示「未识别到旅行攻略内容，请尝试其他视频」，不生成模块卡片

### F-003 模块卡片生成

**AC-F003-01：卡片类型完整性（正常路径）**
Given AI 成功解析了包含景点、餐厅和避坑信息的视频
When 解析完成后
Then 系统生成景点卡、餐厅卡、避坑卡三种类型，每张卡片包含：名称、地址、图片缩略图、关键信息摘要

**AC-F003-02：卡片折叠/展开（正常路径）**
Given 模块卡片已生成
When 用户点击卡片
Then 卡片展开显示详细信息（开放时间、人均消费、推荐时长、注意事项等）

**AC-F003-03：信息缺失处理（边界条件）**
Given AI 解析出某个景点但未能获取地址信息
When 生成卡片时
Then 地址字段显示「地址待补充」，其他可用信息正常展示，卡片可用

### F-004 可视化拼装画布

**AC-F004-01：拖拽拼装（正常路径）**
Given 画布上已有 3 张模块卡片
When 用户长按并拖动卡片 A 到卡片 B 前方
Then 卡片 A 插入到卡片 B 之前，整体序列实时更新，卡片位置平滑过渡

**AC-F004-02：删除卡片（正常路径）**
Given 画布上有多张卡片
When 用户将卡片拖拽到画布底部删除区域
Then 该卡片从画布移除，剩余卡片自动重新排列，删除操作可撤销（显示撤销提示 3 秒）

**AC-F004-03：分日编排（正常路径）**
Given 用户拼装了一个 2 天行程
When 用户点击「+ 添加一天」
Then 画布新增 Day 2 区域，用户可将卡片拖拽至不同日期区域

**AC-F004-04：空画布状态（边界条件）**
Given 画布上所有卡片被删除
When 画布为空时
Then 显示空状态提示「拖拽模块卡片到这里开始拼装你的行程」，并提供「重新解析视频」快捷入口

### F-008 避坑提醒标注

**AC-F008-01：避坑标签展示（正常路径）**
Given 视频解析结果中包含避坑信息
When 生成对应模块卡片时
Then 该卡片右上角显示红色「避坑」角标，点击展开显示具体避坑内容

**AC-F008-02：避坑卡片独立展示（正常路径）**
Given 视频中有不与具体地点绑定的通用避坑建议
When 解析完成后
Then 系统生成独立的「通用避坑」卡片，归类在画布侧边栏的「贴士区」

**AC-F008-03：避坑信息优先级（边界条件）**
Given 某景点同时包含推荐和避坑信息
When 展示卡片时
Then 避坑信息以醒目颜色（红色/橙色）前置展示，推荐信息以常规颜色后置展示

## 10. 技术可行性评估

### 10.1 关键技术决策

| 决策项 | 方案 | 备选方案 | 理由 |
|--------|------|----------|------|
| 视频解析模型 | 多模态大模型（GPT-4V / Claude / 国内文心/通义） | 自研 CV+NLP 流水线 | MVP 使用 API 快速验证，自研成本高 |
| 视频获取 | 抖音官方开放平台 API | 网页爬虫 | 合规优先，爬虫有法律风险 |
| 地图服务 | 高德地图 JS API | 百度地图 | 国内体验好，路线规划精确 |
| 前端框架 | React + Canvas 引擎 | Flutter | Web 跨平台，拼装交互生态成熟 |
| 数据存储 | PostgreSQL + Redis | MongoDB | 结构化关系数据多，PostgreSQL 更适合 |

### 10.2 接口契约（关键）

**视频解析服务**
- 输入：视频 URL 或文件流 + 平台标识
- 输出：JSON 数组，每项包含 `type`(spot/dining/transport/accommodation/tip/budget)、`name`、`location`、`description`、`price`、`warnings`、`images`、`confidence_score`
- 超时：30s，异步回调模式

### 10.3 第三方依赖

| 服务 | 用途 | 降级方案 |
|------|------|----------|
| 抖音开放平台 | 获取视频元数据 | 仅支持录屏上传 |
| 多模态 AI API | 视频内容解析 | 返回「解析失败，请手动输入」 |
| 高德地图 API | 地理编码 + 路线规划 | 不显示地图，纯列表展示 |

## 11. 假设、约束与风险

### 11.1 假设

- 用户主要使用抖音平台获取旅游攻略视频（占 70%+）
- AI 多模态模型对中文旅游攻略视频的解析准确率可达 80% 以上
- 目标用户群体（18-35 岁）对拖拽式交互有基本认知
- 抖音开放平台允许获取视频内容用于解析目的

### 11.2 约束

- **技术约束**：MVP 阶段视频时长限制 ≤5 分钟，超出需分段处理
- **合规约束**：视频解析需遵守《生成式人工智能服务管理暂行办法》，输出内容需安全过滤
- **预算约束**：AI API 调用成本需控制在单次解析 ¥0.5 以内
- **时间约束**：MVP 需在 8 周内上线

### 11.3 风险登记册

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 抖音开放平台政策变动，限制视频内容获取 | 高 | 中 | 同时支持录屏上传作为备选输入方式 |
| AI 解析准确率低于预期（<70%），用户体验差 | 高 | 中 | 建立人工审核机制，低置信度结果引导用户手动修正 |
| 视频解析 API 成本过高，单用户成本超预算 | 中 | 低 | 设置每日免费解析次数上限，超出收费或引导邀请 |
| 竞品（抖音官方）推出类似功能 | 高 | 中 | 快速建立品牌认知，深耕拼装体验差异化 |
| 用户隐私顾虑，不愿提交视频链接 | 中 | 低 | 明确隐私政策，支持本地录屏不上传原始视频 |
